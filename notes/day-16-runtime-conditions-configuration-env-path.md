## 2. 程序运行条件

程序运行条件是程序正常启动和完成任务所依赖的一组外部条件。

常见运行条件包括：

| 运行条件 | 解决的问题 | 例子 |
| --- | --- | --- |
| 参数 | 本次运行要怎么做 | `java -version` 中的 `-version` |
| 配置文件 | 长期默认规则是什么 | 服务端口、日志位置、项目配置 |
| 环境变量 | 当前系统或环境提供哪些公共信息 | `PATH`、`JAVA_HOME`、临时目录 |
| 当前目录 | 相对路径从哪里开始找 | `Get-Content .\abc.txt` |
| 路径 | 程序要访问哪个文件或目录 | 文件路径、安装路径、日志路径 |
| 权限 | 当前用户能不能访问或执行 | 读写文件、访问系统目录 |
| 端口 | 服务能不能占用指定入口 | 8080 端口被占用 |
| 依赖 | 程序需要的外部工具、库或服务是否存在 | JDK、数据库、配置文件、运行库 |

## 3. 参数、配置文件、环境变量的区别

### 参数

参数是这一次执行命令时临时传给程序的信息。它通常影响“这次怎么运行”。

例子：

```powershell
java -version
Get-ChildItem -Path . -File
```

`-version`、`-Path .`、`-File` 都会改变命令行为。

### 配置文件

配置文件是保存程序长期规则的文件。它通常影响“默认怎么运行”。

比如一个服务默认监听哪个端口、日志写到哪里、启动时读取哪些目录，这些都可能来自配置文件。

### 环境变量

环境变量是系统或当前环境提供给程序读取的键值对配置。

重要修正：

```text
不是所有环境变量都是用来找应用的。
PATH 是环境变量中的一种，它专门帮助 Shell 查找外部命令。
```

## 4. PATH 的作用和边界

PATH 是一个特殊的环境变量。它的值是一串目录。

当我在 Shell 中输入 `java` 这种外部命令名时，Shell 会根据 PATH 中的目录去找 `java.exe`。

PATH 解决：

```text
输入命令名时，Shell 去哪些目录里找可执行文件。
```

PATH 不能解决：

```text
程序参数是否正确
文件是否存在
配置是否完整
权限是否足够
端口是否被占用
依赖是否齐全
程序启动后是否成功
```

## 5. 当前目录和相对路径

当前目录会影响相对路径。

例如：

```powershell
Get-Content .\abc.txt
```

这里的 `.` 指当前目录。换一个当前目录，`.\abc.txt` 指向的位置就会变，所以结果也可能不同。

因此，看到“找不到路径”时，应该先检查：

```powershell
Get-Location
Test-Path .\abc.txt
```

## 6. 端口、权限和依赖

### 端口

如果程序是服务类程序，它可能需要监听某个端口。端口被占用时，服务可能无法启动。

检查方向：

```powershell
Get-NetTCPConnection -State Listen
```

### 权限

权限不足说明当前用户或程序没有权限访问某个文件、目录、端口、系统资源或执行某个操作。它可能导致程序无法启动，也可能导致程序启动后某一步失败。

### 依赖

依赖是程序运行需要的其他工具、库、配置或服务。程序本身存在，不代表所有依赖都满足。

例如：命令能找到，但缺少配置文件、缺少运行环境、连接不上数据库或端口被占用，程序仍然可能失败。

## 7. Day16 排错顺序

当命令能找到，但程序仍然失败时，排查范围要从“命令是否存在”扩展到“运行条件是否满足”。

推荐顺序：

```text
1. 先看完整错误信息。
2. 判断是命令找不到、路径找不到，还是程序运行条件不满足。
3. 检查参数是否正确。
4. 检查配置文件是否存在或配置是否正确。
5. 检查环境变量，尤其是 PATH、JAVA_HOME 等相关变量。
6. 检查当前目录和相对路径。
7. 检查权限、端口和依赖。
8. 必要时看退出码和日志。
9. 用明确命令验证猜测。
```
