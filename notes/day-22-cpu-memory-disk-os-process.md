主题：操作系统如何管理程序运行：CPU、内存、硬盘、程序文件与进程之间的关系  

## 1. 今日核心问题

一个程序从硬盘上的文件变成正在运行的进程时，CPU、内存、硬盘和操作系统分别做了什么？

## 2. 核心理解

硬盘负责长期保存文件，包括程序文件、源代码、配置文件和普通数据。程序没有运行时，它只是硬盘上的静态文件。

内存负责给正在运行的程序提供临时、高速的运行空间。程序启动后，操作系统会把运行所需的内容加载到内存中，并为进程分配运行资源。

CPU 负责执行程序中的指令。更准确地说，CPU 不是直接“执行文件”，而是在操作系统调度下执行进程中的指令。

操作系统负责协调 CPU、内存、硬盘和进程。它会接收启动请求，找到程序文件，创建进程，分配内存，调度 CPU，并管理程序运行过程中对文件、端口等资源的访问。

## 3. 程序文件如何变成进程

```text
程序文件保存在硬盘上
→ 用户双击图标或在 Shell 中输入启动命令
→ Shell 或 IDE 找到对应的程序入口
→ 操作系统加载程序运行所需内容
→ 操作系统创建进程并分配进程 ID
→ 进程获得内存等资源
→ CPU 在操作系统调度下执行进程中的指令
→ 如果它是服务程序，可能会监听端口等待请求
```

这条链路接上了 Week03 的内容：程序启动后才可能变成进程，服务进程启动后才可能监听端口，`localhost:端口` 才可能访问到本地服务。

## 4. 文件存在不等于程序正在运行

文件存在只说明硬盘上有这个程序或代码。它可能只是一个 `.exe`、`.java`、`.class` 或项目文件，还没有被操作系统启动。

程序正在运行，通常意味着操作系统已经创建了对应进程，并且可以在任务管理器或 `Get-Process` 中观察到它。

## 5. 进程存在说明什么

进程存在说明某个程序已经被启动成运行实例。进程一定是运行中的，不是静态文件。

进程可以有不同表现：

- 前台程序：需要用户直接操作，通常有窗口或终端交互。
- 后台程序：可以没有明显窗口，但仍在运行。
- 服务进程：在后台运行，并可能监听端口等待请求。

要注意：后台进程也是动态运行状态，不是静态状态。静态的是硬盘上的程序文件。

## 6. 今日命令观察

常用观察命令：

```powershell
Get-Process
Get-Process | Sort-Object CPU -Descending | Select-Object -First 10 Name,Id,CPU,WorkingSet
Get-Process | Sort-Object WorkingSet -Descending | Select-Object -First 10 Name,Id,CPU,WorkingSet
Get-CimInstance Win32_OperatingSystem | Select-Object TotalVisibleMemorySize,FreePhysicalMemory
Get-Volume
Get-Command java
java -version
Get-NetTCPConnection -State Listen | Select-Object -First 10 LocalAddress,LocalPort,State,OwningProcess
```

观察重点：

- `Get-Process` 显示正在运行的进程，不显示硬盘上的全部程序文件。
- `Id` 或 PID 是进程编号。
- `CPU` 是进程使用 CPU 的累计情况，不是程序大小。
- `WorkingSet` 可以粗略理解为进程当前占用的一部分物理内存。
- `Get-Volume` 观察的是硬盘卷和空间，不是内存。
- `Get-Command java` 检查 Shell 能否找到 Java 命令。
- `java -version` 会真正启动 Java 程序并让它输出版本信息。
- `OwningProcess` 是占用监听端口的进程 ID。

## 7. 今日最容易混淆的点

1. CPU 不是执行“进程这个概念”，而是执行进程中的指令。
2. 内存和硬盘都是存储空间，但内存用于运行时临时空间，硬盘用于长期保存文件。
3. 程序文件是静态的；进程是程序运行后的动态实例。后台进程也是运行中的进程。
4. 操作系统不是只负责分配内存，还负责创建进程、调度 CPU、管理文件和资源。
5. 服务进程监听端口，是程序运行后的表现，不是程序文件本身的属性。
