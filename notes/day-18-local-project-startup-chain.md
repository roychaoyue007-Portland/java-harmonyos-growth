## 1. 今天的核心问题

为什么“打开项目目录”不等于“项目已经运行”？

打开项目目录只能说明项目文件存在，开发工具能看到这些文件；但项目真正运行起来，还需要执行启动命令，让操作系统创建进程。如果这是服务类程序，它还需要成功监听端口，之后才可能通过 `localhost:端口` 访问。

今天的主线是：

```text
打开开发工具
→ 打开项目目录
→ 工具识别代码、配置和依赖
→ 执行启动命令
→ Shell 或 IDE 找到语言工具 / 运行工具
→ 工具读取参数、配置文件和环境变量
→ 操作系统创建进程
→ 服务进程监听本地端口
→ 通过 localhost:端口 访问服务
→ 如果失败，看错误信息和启动日志
```

## 2. 打开项目和运行项目的区别

打开项目：

```text
让 IDE 或编辑器看到项目目录里的文件。
```

运行项目：

```text
执行启动命令，让程序从静态文件变成正在运行的进程。
```

所以：

```text
看到项目文件夹，不等于项目已经启动。
打开 IDE，不等于服务已经启动。
执行启动命令成功，也不等于端口一定可访问。
```

## 3. 项目目录的作用

项目目录告诉工具：当前要处理哪个项目。

工具可能会从项目目录里查找：

```text
源代码
配置文件
依赖声明
资源文件
启动入口
日志目录
输出目录
相对路径指向的文件
```

所以项目目录不只是“项目的位置”，它还是工具识别项目结构、读取配置和解析相对路径的起点。

## 4. 启动命令的作用

启动命令是正式请求项目运行的指令。

它解决的是：

```text
让工具或运行时按照当前项目的代码、配置和参数启动程序。
```

启动命令可能来自：

```text
终端输入的命令
IDE 的运行按钮
项目脚本
构建工具或运行工具
```

命令执行后，Shell 或 IDE 会找到对应的语言工具或运行工具，再由工具读取项目内容并启动程序。

## 5. Shell、PATH 和语言工具的关系

Shell 负责解析命令。

PATH 负责告诉 Shell：去哪些目录里找外部命令。

语言工具负责处理代码或启动程序。

例如：

```text
用户输入 java -version
→ Shell 解析命令名 java 和参数 -version
→ Shell 根据 PATH 找 java.exe
→ 找到后启动 Java 工具
→ Java 工具输出版本信息
```

注意：PATH 只帮助 Shell 找命令，不保证项目一定能启动成功。

## 6. 配置文件和环境变量

配置文件影响项目按什么规则启动和运行，例如：

```text
端口
日志路径
依赖配置
默认参数
项目运行规则
```

环境变量提供系统或当前环境级信息，例如：

```text
PATH
JAVA_HOME
临时目录
工具安装路径
运行环境标记
```

需要记住：

```text
环境变量不只是“找到运行项目”。
PATH 才是专门帮助 Shell 找语言工具或外部命令的环境变量。
```

## 7. 进程、服务和端口

程序文件是静态的，保存在硬盘上。

程序启动后，操作系统会创建进程。进程是正在运行的程序实例。

服务不是“静态进程”。服务启动后也是一个正在运行的进程，只是它通常长期在后台运行，并等待请求。

服务程序的典型链路是：

```text
服务进程已经启动
↓
它监听某个端口
↓
等待客户端请求
↓
请求来了再处理并返回结果
```

## 8. localhost:8080 访问失败的可能原因

`localhost:8080` 可以拆成：

```text
localhost：当前这台电脑
8080：当前电脑上的一个端口
localhost:8080：访问当前电脑上 8080 端口对应的服务入口
```

访问失败不只可能是 8080 端口被占用，还可能是：

```text
服务没有启动
服务启动失败
服务启动后又退出了
端口不是 8080
服务监听了别的地址
配置文件端口写错
防火墙或权限问题
程序报错退出了
```

## 9. Day18 排错顺序

本地项目启动失败时，可以按这个顺序排查：

```text
1. 先看完整错误信息。
2. 确认当前目录是否是项目目录。
3. 确认启动命令是否正确。
4. 确认语言工具和运行时是否能执行。
5. 检查 PATH、JAVA_HOME 等环境变量。
6. 检查配置文件，尤其是端口、路径和依赖配置。
7. 检查程序是否已经启动成进程。
8. 检查端口是否正在监听。
9. 查看启动日志。
10. 根据证据逐一验证，而不是盲目重试。
```
