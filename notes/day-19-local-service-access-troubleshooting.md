## 2. 项目打开和服务可访问的区别

项目已经打开，不代表项目已经运行，更不代表服务可以访问。

正确区分：

```text
项目打开：项目文件被 IDE 或编辑器加载和识别。
服务可访问：程序已经启动成进程，并且成功监听端口，可以被 localhost:端口 访问。
```

今天验收中的一个重要修正是：

```text
项目打开不等于从文件或文件夹变成进程。
项目打开只是开发工具看到了项目文件。
```

## 3. 访问失败不能只说端口被占用

`localhost:8080` 访问失败时，不能直接判断为“8080 端口被占用”。

可能原因包括：

```text
服务根本没有启动
服务启动失败
服务启动后很快退出
服务启动了，但没有监听端口
服务监听的是 3000，不是 8080
访问地址或路径写错
配置文件中的端口写错
权限、防火墙或本机网络规则影响访问
程序有错误，日志里有异常信息
```

排查时要根据错误信息、进程、端口、配置和日志来判断。

## 4. 什么是监听端口

监听端口是服务进程打开某个端口，并等待客户端连接请求。

它不是“监听通知”，更准确的顺序是：

```text
服务进程启动
↓
服务进程监听某个端口
↓
客户端发起请求
↓
服务进程处理请求
↓
服务进程返回响应
```

## 5. 服务进程和监听端口的关系

服务进程是正在运行的程序实例。

监听端口是这个服务进程对外等待请求的入口。

可以这样记：

```text
进程负责运行服务。
端口负责让外部或本机客户端找到这个服务。
```

一个进程可以监听一个或多个端口；一个端口在同一时间通常只能被一个进程监听。

## 6. PowerShell 中查看监听端口

查看当前有哪些端口正在监听：

```powershell
Get-NetTCPConnection -State Listen
```

只看前 20 条：

```powershell
Get-NetTCPConnection -State Listen | Select-Object -First 20
```

检查 8080：

```powershell
Get-NetTCPConnection -State Listen | Where-Object LocalPort -eq 8080
```

或者：

```powershell
Get-NetTCPConnection -LocalPort 8080 -ErrorAction SilentlyContinue
```

注意：不是 `Listsen` 指令。`Listen` 是监听状态，完整命令通常是 `Get-NetTCPConnection -State Listen`。

## 7. OwningProcess 是什么

`OwningProcess` 表示占用这个连接或监听端口的进程 ID。

它不是“当前进程”。

可以用它反查进程：

```powershell
Get-Process -Id 进程ID
```

这里的 `进程ID` 要替换成 `OwningProcess` 里看到的数字。

## 8. Test-NetConnection 能观察什么

测试本机 8080 端口是否能连接：

```powershell
Test-NetConnection localhost -Port 8080
```

重点看：

```text
TcpTestSucceeded: True  表示连接测试成功
TcpTestSucceeded: False 表示连接测试失败
```

它能帮助判断当前电脑的某个端口是否可以建立连接，但不能单独解释所有失败原因。

## 9. Day19 推荐排查顺序

本地服务访问失败时，可以按这个顺序排查：

```text
1. 先看错误信息或浏览器提示。
2. 检查服务程序是否已经启动成进程。
3. 检查目标端口是否正在监听。
4. 如果 8080 没监听，检查服务是否启动失败、是否退出、是否监听了别的端口。
5. 如果端口在监听，确认访问地址、端口和路径是否正确。
6. 检查配置文件中的端口和路径配置。
7. 查看启动日志和错误日志。
8. 用明确命令验证猜测，而不是只凭感觉重试。
```

