## 1. 今日核心问题

程序运行时的数据从哪里来，又会被输出到哪里？

## 2. 程序为什么需要输入和输出

程序不是凭空工作的。输入是进入程序的数据，输出是程序处理后给出的结果。没有输入，程序通常没有内容可处理；没有输出，程序的处理结果就无法被用户、文件或其他程序接收。

输入可以来自终端、文件、网络、参数或其他程序。输出可以显示在终端、写入文件、通过网络发送给其他服务，也可以作为管道数据交给下一条命令。

## 3. 文件输入、终端输入和网络输入

文件输入是程序从硬盘上的文件读取数据。文件存在只说明数据保存在硬盘上，不代表程序已经读取了它。只有程序执行读取动作后，文件内容才会变成程序的输入。

终端输入是用户在终端里直接输入给程序或命令的数据。它更像临时交互。

网络输入可以先粗略理解为程序从另一台电脑、服务或客户端收到的数据。今天不深入网络协议，只建立“数据也可以从网络来”的意识。

## 4. 文件输出、终端输出和错误输出

终端输出通常用于展示结果，让用户立即看到。它默认只是显示，不会自动保存。

文件输出用于把结果写入硬盘上的文件，方便长期保存、后续读取或交给其他程序使用。

错误输出是程序失败或异常时给出的线索。它和正常输出不同，通常包含错误原因、路径、命令名或失败位置。PowerShell 中错误信息常见为红色显示，但真正重要的是错误内容本身。

## 5. 今日命令

```powershell
Get-Location
New-Item -ItemType Directory -Force .\practice\day-23
Set-Content .\practice\day-23\input.txt "hello day 23"
Get-Content .\practice\day-23\input.txt
Write-Output "this is terminal output"
Write-Output "this is file output" | Out-File .\practice\day-23\output.txt
Get-Content .\practice\day-23\output.txt
Add-Content .\practice\day-23\output.txt "second line"
Get-Content .\practice\day-23\output.txt
Get-Content .\practice\day-23\output.txt | Select-Object -First 1
Get-Content .\practice\day-23\output.txt | Measure-Object -Line
Get-Content .\practice\day-23\not-exist.txt
```

命令理解：

- `Get-Content`：读取文件内容。
- `Set-Content`：覆盖写入文件。
- `Add-Content`：追加写入文件。
- `Write-Output`：把内容输出到终端或管道。
- `Out-File`：把输出写入文件。
- `|`：把上一条命令的输出交给下一条命令。

## 6. 管道和重定向

管道解决的是“把一个命令的输出交给下一个命令作为输入”的问题。比如先读取文件，再筛选第一行，或统计行数。

重定向或 `Out-File` 解决的是“把本来显示在终端的输出改到文件里保存”的问题。显示在终端只是临时展示，写入文件才会保存到硬盘。

## 7. 今天最容易混淆的点

1. 文件保存在硬盘上，不等于程序已经读取了文件。
2. 显示在终端不等于保存到文件。
3. `Set-Content` 是覆盖写入，`Add-Content` 是追加写入。
4. 管道是命令之间传递数据，文件写入是把数据保存到硬盘。
5. 错误输出不仅是“红色”，更重要的是它提供失败原因和排错线索。
