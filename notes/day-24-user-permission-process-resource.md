## 1. 今日核心问题

为什么文件或端口明明存在，程序却可能没有权限访问？

## 2. 用户、进程、资源、权限

用户是操作系统里执行操作的身份。当前用户会影响命令、程序和进程可以访问哪些资源。

进程是程序运行后的实例。命令启动程序后，操作系统会创建进程，而这个进程通常会带着当前用户的权限身份去访问文件、目录、端口等资源。

资源是操作系统管理的对象，不只包括文件，还包括 CPU、内存、硬盘文件、目录、端口、网络连接、进程和设备等。

权限表示当前用户或进程是否被允许访问某个资源。常见权限包括读取、写入、创建、删除、执行和监听端口等。

## 3. 文件存在不等于可以读取

文件存在只说明硬盘上有这个文件。当前用户或进程是否能读取它，还要看权限是否允许。

如果读取失败，需要区分：

- 路径是否写错。
- 文件是否真的存在。
- 当前用户是否有读取权限。
- 文件是否被其他程序占用。
- 是否访问了受保护目录。

## 4. 路径正确不等于可以写入

路径正确只说明系统能定位到目标位置。写入还需要写入权限。

比如当前学习目录一般可以写入，但系统目录、其他用户目录或受保护位置可能不允许普通用户写入。此时错误不是“找不到路径”，而可能是“访问被拒绝”或“权限不足”。

## 5. 程序运行不等于有权访问所有资源

程序启动成进程后，仍然要受操作系统管理。进程访问文件、目录、端口、网络连接等资源时，操作系统会检查资源是否存在、当前用户身份、权限规则和资源状态。

所以“进程存在”只说明程序正在运行，不代表它能访问所有文件或端口。

## 6. 文件权限和端口访问的共同点

文件访问和端口访问都属于“进程访问资源”。它们都可能因为资源不存在、路径或地址错误、权限不足、端口被占用、配置错误、防火墙或服务内部错误而失败。

```text
当前用户运行命令
→ 命令拉起进程
→ 进程访问文件、目录、端口或网络资源
→ 操作系统检查资源是否存在、权限是否允许、状态是否可用
→ 返回正常结果或错误信息
```

## 7. 今日命令

```powershell
Get-Location
New-Item -ItemType Directory -Force .\practice\day-24
whoami
Get-ChildItem .\practice\day-24
Set-Content .\practice\day-24\permission-demo.txt "day 24 permission demo"
Get-Content .\practice\day-24\permission-demo.txt
Get-Item .\practice\day-24\permission-demo.txt | Select-Object FullName,Length,Attributes,LastWriteTime
Get-Content .\practice\day-24\not-exist.txt
Get-ChildItem C:\Windows | Select-Object -First 5 Name,Mode,LastWriteTime
Set-Content .\practice\day-24\write-test.txt "write ok"
Get-Content .\practice\day-24\write-test.txt
Get-NetTCPConnection -State Listen | Select-Object -First 10 LocalAddress,LocalPort,State,OwningProcess
```

命令理解：

- `whoami`：查看当前用户。
- `Get-Content`：尝试读取文件。
- `Set-Content`：尝试写入文件。
- `Get-Item`：查看文件属性。
- `Get-NetTCPConnection -State Listen`：查看监听端口和占用端口的进程 ID。
- `Get-Process -Id 进程ID`：根据进程 ID 反查进程。

## 8. 今天最容易混淆的点

1. 文件存在、路径正确、权限允许是三个条件。
2. 资源不只包括文件，也包括端口、进程、内存、网络连接等。
3. 程序运行不等于它有权访问所有资源。
4. 权限错误和路径不存在是不同问题。
5. 端口或服务存在，不代表访问一定成功。
