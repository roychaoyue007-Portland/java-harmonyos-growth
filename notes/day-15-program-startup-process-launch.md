## 2. 程序文件和进程

程序文件是硬盘上的静态内容，例如一个 `.exe` 文件、一个命令行工具或一个已安装软件的启动文件。

进程是程序启动后的运行实例。程序文件本身只是“放在那里”，只有被操作系统启动后，才会变成任务管理器或 `Get-Process` 中能看到的进程。

一句话记忆：

```text
程序文件是静态的，进程是运行起来的程序。
```

## 3. 双击软件和命令行启动的共同点

双击软件和在 PowerShell 输入命令，看起来操作方式不同，但本质上都是在请求操作系统启动一个程序。

区别主要在“如何找到程序”：

- 双击软件：通常通过快捷方式、开始菜单或文件路径找到程序文件。
- 输入命令：Shell 先解析命令名，如果不是内置命令，就通过 PATH 去查找外部程序文件。

共同点是：最终都要让操作系统找到程序文件，加载它，分配运行资源，并创建进程。

## 4. PATH 在启动链路中的位置

PATH 只解决一个问题：当我输入 `java` 这样的外部命令名时，Shell 应该去哪些目录里寻找 `java.exe`。

PATH 不能保证：

- Java 一定已经安装。
- 找到的 Java 版本一定正确。
- 程序启动后一定成功。
- 参数、配置、权限、依赖和端口都没有问题。

所以：

```text
PATH 解决“找得到命令”。
但程序能不能成功运行，还要看启动后的运行条件。
```

## 5. 程序启动失败的常见原因

程序启动失败不只有“命令找不到”。常见原因包括：

| 类型 | 典型表现 | 排查方向 |
| --- | --- | --- |
| 命令找不到 | `not recognized`、`Get-Command` 找不到 | 检查安装和 PATH |
| 路径不存在 | `Get-Content .\abc.txt` 找不到路径 | 检查当前目录和文件路径 |
| 参数错误 | 程序能启动，但提示参数不支持 | 检查命令参数写法 |
| 配置缺失 | 程序启动后缺少配置项 | 检查配置文件或环境变量 |
| 权限不足 | 提示 access denied 或 permission | 检查用户权限和文件访问权限 |
| 端口被占用 | 服务启动失败，端口已被使用 | 检查监听端口和占用进程 |
| 依赖缺失 | 程序需要的组件不存在 | 检查运行环境和依赖安装 |

## 6. Day 15 排错顺序

程序启动失败时，推荐按这个顺序排查：

```text
1. 先看完整错误信息。
2. 判断是命令找不到、路径找不到，还是程序启动后失败。
3. 检查当前目录和路径。
4. 如果是外部命令，检查 PATH 和 Get-Command。
5. 检查参数、权限、配置、端口和依赖。
6. 必要时查看退出码和日志。
7. 用一条明确命令验证自己的猜测。
```

不要只说“启动失败”或“报错了”。真正有用的是完整命令、当前目录、完整错误信息和验证步骤。
