# Day 20 练习笔记：开发环境综合排错

## 1. 今日主题

开发环境综合排错：把命令、路径、环境变量、配置、进程、端口和日志串成一套排查流程。

今天是 Week03 的综合排错训练，不是学习新语法，而是把前几天的概念组织成稳定流程。

## 2. 核心排查链路

```text
发现问题
↓
记录完整现象和错误信息
↓
确认当前目录和项目目录
↓
确认命令、工具和环境变量
↓
确认配置文件
↓
确认进程是否存在
↓
确认端口是否监听
↓
确认访问地址和路径
↓
查看日志
↓
提出原因假设
↓
用明确命令验证
```

## 3. 今日重点修正

1. “报错了”只是现象，不能直接定位原因。
2. 配置文件不只影响端口，也可能影响日志路径、文件路径、运行模式、访问路径和服务功能。
3. 服务不是静态进程；服务启动后才成为正在运行的进程。
4. 进程存在不等于目标端口一定监听。
5. 端口监听正常不等于访问路径一定正确。
6. 日志记录程序运行过程、错误上下文和失败原因。

## 4. 建议观察命令

```powershell
Get-Location
Get-ChildItem .
Get-Command java
java -version
$env:PATH
$env:JAVA_HOME
Get-Process | Select-Object -First 10
Get-NetTCPConnection -State Listen | Select-Object -First 20
Get-NetTCPConnection -State Listen | Select-Object LocalAddress,LocalPort,OwningProcess -First 10
Test-NetConnection localhost -Port 8080
not-a-real-command
Get-Content .\not-exist-file.txt
```

## 5. 综合排查记录模板

```text

当前目录：

工具是否能运行：
环境变量是否相关：
配置文件可能在哪里：
进程是否存在：
端口是否监听：
访问地址是否正确：
日志或错误信息说明了什么：
我猜测的原因：
我用什么命令验证：
验证结果：
```

## 6. 今日薄弱点

1. 配置文件影响范围需要继续扩大理解。
2. “服务是静态进程”这个说法要彻底改掉。
3. 日志的作用要从“看看错误”升级成“查看运行过程、上下文和失败原因”。
4. 抽象排错流程要能落回具体问题。

## 7. 今日复盘

今天真正学会的是：排错不是靠猜，而是按层次缩小范围。先看完整错误信息，再检查目录、命令、工具、环境变量、配置、进程、端口、访问地址和日志，最后提出原因假设并验证。

最重要的一句话：

```text
先收集证据，再提出假设，最后用明确命令验证。
```
