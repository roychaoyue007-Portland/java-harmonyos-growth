# Day 15 练习答案：程序启动链路

## 1. 今日核心流程整理

```text
用户发起启动
→ Shell 或系统找到程序文件
→ 操作系统加载程序
→ 分配内存和运行资源
→ 创建进程
→ 程序开始执行
→ 读取参数、配置或环境变量
→ 输出正常结果、错误信息或日志
```

## 2. 程序文件与进程

原回答：

> 程序文件是存放在硬盘上的静态的内容；进程是运行起来的程序

整理：

程序文件是硬盘上的静态内容；进程是程序启动后由操作系统创建出来的运行实例。

## 3. 双击软件与命令行启动

原回答：

> 都是打开软件，最终都是将静态的程序变成进程

整理：

双击软件和输入命令，本质上都是让操作系统启动某个程序。最终结果都是把硬盘上的静态程序文件加载为运行中的进程。

## 4. PATH 的作用与边界

原回答：

> 找到程序所在位置；不能解决程序是否存在，程序启动是否正常等

整理：

PATH 解决的是：当我输入 `java` 这样的外部命令名时，Shell 去哪些目录里找 `java.exe`。

PATH 不能保证：

- 程序一定已经安装。
- 找到的版本一定正确。
- 程序启动后一定成功。
- 参数、配置、权限、依赖和端口都没问题。

## 5. Java 安装与命令可运行

原回答：

> 安装只是让程序在电脑上存在，没有配置java环境，是无法运行java命令的

整理：

安装 Java 只是让 `java.exe` 存在于硬盘上。只有当 `java.exe` 所在目录被加入 PATH，PowerShell 才能直接通过 `java` 这个命令名找到它。

## 6. 命令找到与程序成功运行

原回答：

> 程序不只有找不到命令的错误，还可能有输入的命令程序不支持等问题

整理：

`java` 命令能找到，只代表 Shell 找到了并启动了 `java.exe`。但 Java 程序仍可能因为参数错误、类名不存在、classpath 不对、配置缺失、权限问题或依赖缺失而运行失败。

## 7. 安全错误分类

原回答：

> 找不到命令

整理：

`not-a-real-command` 更像命令找不到，应该检查命令名、安装和 PATH。

原回答：

> 找不到文件

整理：

`Get-Content .\abc.txt` 报找不到路径，更像当前目录或文件路径问题，应该检查 `Get-Location` 和 `Test-Path .\abc.txt`。

## 8. 基础排查顺序

原回答：

> 先解读报错信息，再按报错信息定位

整理：

```text
1. 先看完整错误信息。
2. 判断是命令找不到、路径找不到，还是程序启动后失败。
3. 检查当前目录和路径。
4. 如果是外部命令，检查 PATH 和 Get-Command。
5. 检查参数、权限、配置、端口和依赖。
6. 必要时查看退出码和日志。
7. 用一条明确命令验证猜测。
```

## 9. 用户发起启动到程序变成进程

原回答：

> 计算机根据path找到程序，给程序分配内存

整理：

```text
用户发起启动
→ Shell 或系统找到程序文件
→ 操作系统加载程序
→ 分配内存和运行资源
→ 创建进程
→ 程序开始执行
→ 读取参数、配置或环境变量
→ 输出结果、错误信息或日志
```

补充：PATH 只在“通过命令名查找外部程序”时参与；双击软件不一定经过 Shell 的 PATH 查找。
