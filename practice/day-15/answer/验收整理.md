## 总体评价

Day15 的核心目标是把第一周和第二周内容合成一条真实启动链路：从用户发起启动，到操作系统创建进程，再到程序输出结果或报错。

你的整体理解是过关的。尤其是“程序文件是静态的，进程是运行起来的程序”“双击和命令行本质上都是启动程序”“找不到命令和找不到文件是不同问题”这些点已经比较稳。

主要需要补强的是：PATH 的边界、命令找到后仍可能运行失败、以及完整启动链路中的中间步骤。

## 题目 1：程序文件和进程有什么区别？

原回答：

> 程序文件是存放在硬盘上的静态的内容；进程是运行起来的程序

评分：10 / 10

整理：

程序文件是硬盘上的静态内容；进程是程序启动后由操作系统创建出来的运行实例。

需要记住：

```text
程序文件是静态的，进程是运行中的。
```

## 题目 2：双击软件和在 PowerShell 输入命令，本质上有什么共同点？

原回答：

> 都是打开软件，最终都是将静态的程序变成进程

评分：10 / 10

整理：

两者本质上都是请求操作系统启动某个程序，最终把硬盘上的程序文件加载成运行中的进程。

## 题目 3：PATH 在程序启动链路中解决的是什么问题？它不能解决什么问题？

原回答：

> 找到程序所在位置；不能解决程序是否存在，程序启动是否正常等

评分：8 / 10

整理：

PATH 解决的是：当我输入 `java` 这样的命令名时，Shell 去哪些目录里找 `java.exe`。

PATH 不能解决：程序是否真的安装、版本是否正确、参数是否正确、配置是否存在、权限是否足够、依赖是否齐全、端口是否可用、程序启动后是否成功。

## 题目 4：为什么“安装了 Java”不等于“PowerShell 一定能运行 java 命令”？

原回答：

> 安装只是让程序在电脑上存在，没有配置java环境，是无法运行java命令的

评分：8 / 10

整理：

安装 Java 只是让 `java.exe` 存在于硬盘上。如果 `java.exe` 所在目录没有加入 PATH，PowerShell 输入 `java` 时就不一定能找到它。

需要记住：

```text
安装解决“程序存在”，PATH 解决“命令能找到”。
```

## 题目 5：为什么“java 命令能找到”不等于“Java 程序一定能成功运行”？

原回答：

> 程序不只有找不到命令的错误，还可能有输入的命令程序不支持等问题

评分：7 / 10

整理：

`java` 命令能找到，只说明 Shell 能找到并启动 `java.exe`。但程序启动后还可能因为参数错误、类名不存在、classpath 不对、配置缺失、权限不足或依赖缺失而失败。

## 题目 6：如果输入 `not-a-real-command` 报错，这更像是什么问题？

原回答：

> 找不到命令

评分：10 / 10

整理：

这是命令找不到。排查方向是命令名是否写错、程序是否安装、PATH 是否配置。

## 题目 7：如果输入 `Get-Content .\abc.txt` 报找不到路径，这更像是什么问题？

原回答：

> 找不到文件

评分：9 / 10

整理：

这是文件或路径找不到。排查方向是当前目录是否正确、相对路径是否正确、文件是否真的存在。

## 题目 8：一个程序启动失败时，你会按什么顺序排查？

原回答：

> 先解读报错信息，再按报错信息定位

评分：7 / 10

整理：

```text
1. 先看完整错误信息。
2. 判断是命令找不到、路径找不到，还是程序启动后失败。
3. 检查当前目录和路径。
4. 如果是外部命令，检查 PATH 和 Get-Command。
5. 检查参数、权限、配置、端口和依赖。
6. 必要时查看退出码和日志。
7. 用一条明确命令验证猜测。
```

## 题目 9：用户发起启动到程序变成进程，中间大概经历了哪些步骤？

原回答：

> 计算机根据path找到程序，给程序分配内存

评分：7 / 10

整理：

```text
用户发起启动
→ Shell 或系统找到程序文件
→ 操作系统加载程序
→ 分配内存和运行资源
→ 创建进程
→ 程序开始执行
→ 读取参数、配置或环境变量
→ 输出结果、错误信息或日志
```

需要记住：

PATH 只在通过命令名查找外部程序时参与。双击软件通常是通过快捷方式或文件路径找到程序。
