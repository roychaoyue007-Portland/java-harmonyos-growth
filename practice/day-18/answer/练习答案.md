# Day 18 练习答案：本地项目启动链路

## 验收题原始回答

1、因为打开目录只能证明项目是存在的，但不是说项目已经运行了。

2、负责对项目进行编辑，对源代码的文件进行人为的处理

3、找到项目的位置

4、给项目发出指令，让它向进程转换

5、path记录如何找到语言工具，shell通过path找到语言工具

6、配置文件影响如何启动这个项目，环境变量影响如何找到运行这个项目

7、服务是一个特殊的静态进程，它依赖于端口监听。只有在有监听过来的时候，它才会执行服务。

8、8080端口被占用

9、先看报错信息，根据报错信息判断具体是什么问题，如缺少java环境就去检查环境是否存在，再对应一一解决即可

10、打开开发工具，加载项目到开发工具中，编辑好自己想要的内容之后，点击运行启动命令。通过什么环境变量之类的，找到找到对应的语言工具去启动命令，然后这个程序就变成了一个进程。在监听这个服务。

## 订正版答案

1、打开项目目录只能证明项目文件存在，并且开发工具能看到这些文件；项目是否运行，要看是否执行了启动命令、是否创建了进程、服务是否监听端口。

2、IDE 或编辑器负责打开项目、编辑代码、识别项目结构，并提供运行、调试、查看错误信息和日志等开发能力。

3、项目目录告诉工具当前要处理哪个项目，也是查找代码、配置文件、依赖、资源和相对路径的起点。

4、启动命令是正式请求项目运行的指令，它让工具或运行时按照当前项目的代码、配置和参数启动程序。

5、Shell 负责解析命令；PATH 告诉 Shell 去哪些目录查找外部命令；语言工具是最终被找到并执行的工具，例如 `java`、`javac`。

6、配置文件影响项目按什么规则启动和运行，例如端口、日志路径、依赖配置；环境变量提供系统或环境级信息，PATH 才是专门帮助 Shell 查找外部命令的环境变量。

7、服务不是静态进程。程序文件是静态的，服务启动后是正在运行的进程。服务进程先监听端口，再等待客户端请求，请求来了再处理并返回结果。

8、`localhost:8080` 访问失败可能是服务没有启动、服务启动失败、服务启动后退出、端口不是 8080、8080 被占用、服务监听了别的地址、配置文件端口写错、防火墙或权限问题等。

9、先看完整错误信息和启动日志，再检查当前目录、启动命令、语言工具和运行时、环境变量、配置文件、进程是否存在、端口是否监听，最后按证据逐一验证。

10、先打开开发工具，这是启动 IDE 或编辑器这个程序。然后在开发工具中打开项目目录，让工具知道当前要处理哪个项目。执行启动命令后，Shell 或 IDE 会根据 PATH、配置和运行环境找到对应的语言工具或运行工具。工具读取项目目录中的代码、配置文件、环境变量和参数，然后操作系统创建进程。如果这是服务程序，它会监听本地端口。监听成功后，就可以通过 `localhost:端口` 访问这个本地服务。
