# Day 18 练习笔记：本地项目启动链路

## 1. 今日主题

本地项目启动链路：从打开项目、执行启动命令，到本地服务可访问。

今天是在 Day17 的基础上，重点补清楚“打开开发工具到本地服务启动”的完整过程。

## 2. 核心主线

```text
打开开发工具
↓
打开项目目录
↓
工具识别代码、配置和依赖
↓
执行启动命令
↓
Shell 或 IDE 找到语言工具 / 运行工具
↓
工具读取参数、配置文件、环境变量和项目文件
↓
程序启动成进程
↓
服务进程监听本地端口
↓
浏览器访问 localhost:端口
```

## 3. 打开项目不等于运行项目

打开项目目录只能说明项目文件存在，并且开发工具可以看到它。

项目运行起来，必须经过启动命令和操作系统创建进程。

服务可访问，还必须满足：

```text
程序已经启动成进程
服务监听了正确端口
访问地址和端口正确
程序没有报错退出
```

## 4. 今日命令观察

建议观察命令：

```powershell
Get-Location
Get-ChildItem .
Get-Command java
java -version
$env:PATH
$env:JAVA_HOME
Get-Process | Select-Object -First 10
Get-NetTCPConnection -State Listen | Select-Object -First 10
not-a-real-command
Get-Content .\not-exist-file.txt
```

观察重点：

- 当前目录影响项目文件和相对路径。
- PATH 帮助 Shell 查找外部命令。
- 命令能找到和命令能正确运行不是同一层问题。
- 程序运行后会成为进程。
- 服务程序通常会监听端口。
- 错误信息是排查的第一线索。

## 5. 排错模板

```text
我执行的启动命令：
当前目录：
完整错误信息：
这是目录问题、命令问题、工具问题、配置问题、环境变量问题、进程问题，还是端口问题：
我检查的配置文件：
我检查的环境变量：
我检查的进程：
我检查的监听端口：
最终判断：
```

## 6. 今日薄弱点

1. 服务不是静态进程，服务启动后是正在运行的进程。
2. 服务监听端口后才等待请求；不是“有监听过来才执行服务”。
3. `localhost:8080` 访问失败不只可能是端口占用。
4. 环境变量提供环境级信息，PATH 才是用于命令查找的环境变量。

## 7. 今日复盘

今天真正理解的是：本地项目启动不是一个动作，而是一条链路。打开项目只是第一步，启动命令会推动工具读取代码、配置和环境，然后程序变成进程。如果是服务程序，还要监听端口，浏览器才能通过 `localhost:端口` 访问。

最重要的一句话：

```text
打开项目只是看到文件；启动成功并监听端口后，服务才可能被 localhost 访问。
```
